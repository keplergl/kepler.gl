# LISA clustering analysis

Use LISA (Local Indicators of Spatial Association, e.g. Local Moran's I) to identify local clusters and spatial outliers for a variable.

## When to use

Use this skill when the user wants to find spatial clusters, hot spots / cold spots, or spatial outliers for a numeric variable across geographic features.

## Workflow

1. If spatial weights are required and not already available, create them first using `executeApi` with `commandId: "geoda.spatial-weights"` and `input: { datasetName, type, k?, orderOfContiguity?, ... }` (queen or knn). The returned `weightsId` is needed for the LISA step.
2. Run the LISA analysis using `executeApi` with `commandId: "geoda.lisa"` and `input: { datasetName, variableName, method, weightsId, permutation?, significanceThreshold?, k?, quantile? }`. `method` is one of: localMoran, localGeary, localG, localGStar, quantileLisa.
3. Save the LISA result as a new dataset and visualize it on the map using `executeApi` with `commandId: "map.add-layer"` and `input: { datasetName, layerType, colorBy, colorType: "unique", colorMap }` using a qualitative color scheme for the cluster labels.
4. Explain the results in context: what the clusters mean, where the hot/cold spots are, and what the spatial outliers indicate.

## Rules

- STRICT RULE: Never use datasets generated from previous LISA tools (dataset name with a "lisa_" prefix) as input for a new LISA analysis.
- For clustering analysis, always perform a spatial statistical test (e.g. Local Moran's I) rather than relying on visual inspection.
- If the input is a road or line dataset, buffer it by 1 meter first (using `executeApi` with `commandId: "geo.spatial-query"`), save the buffered road as a new dataset, and use that for the LISA analysis.
- When a new dataset has been generated by any tool, save it as a new dataset in kepler.gl first, then use that new dataset for the spatial analysis.
